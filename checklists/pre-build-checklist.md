# Pre-Build Checklist

Complete this before asking an agent to make material changes.

## Access and working state

- [ ] Domain access is known and held by the right person.
- [ ] Hosting access is available without sharing credentials in chat or files.
- [ ] Repository access is confirmed.
- [ ] The production branch is identified.
- [ ] A separate working branch will be used.
- [ ] The current known-good state has a named commit or checkpoint.
- [ ] A backup exists where the project requires one.

## Decisions and content

- [ ] The project brief is complete enough to direct the work.
- [ ] The source of truth contains the approved facts and wording.
- [ ] Every required page has one written job.
- [ ] The primary audience and action are clear.
- [ ] Approved assets are available.
- [ ] Asset ownership, licence and provenance are recorded.
- [ ] Settled design decisions are identified.

## Risk and measurement

- [ ] Personal, confidential, employer or client information has been checked.
- [ ] Privacy and legal concerns have an owner.
- [ ] Analytics and other tracking IDs are recorded accurately.
- [ ] Consent requirements are known.
- [ ] Third-party scripts and forms in scope are listed.

## Publication setup

- [ ] The publication mode is understood: manual release or automatic on approval/merge.
- [ ] A non-production preview environment is available.
- [ ] Preview access and indexing behaviour are understood.
- [ ] Preview traffic will not pollute production analytics.
- [ ] The rollback plan has an owner.
